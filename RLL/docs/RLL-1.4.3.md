# 交付说明 — RLL 1.4.3

## 一句话

新增版本：四个实用功能，全部围绕「模组」与「等待」这两个真实痛点。

## 新增了什么

### 1. 安装本地 Mod JAR

**痛点**：从整合包、从朋友那里、或手动下载拿到一个 `.jar`，原本无处安放——
启动器只支持从 Modrinth 安装。

**现在**：模组页新增「安装本地 Mod JAR」按钮，选一个 jar 即可。

- 读出它的模组 id、版本、**必需前置**；
- 明确提示哪些前置还缺（不自动装，避免"装一个 jar 顺带拉一堆代码"）；
- **同名文件绝不覆盖**，自动加 `-2`、`-3` 后缀。

**安全边界**（刻意比整合包导入严格得多）：
只接受单个 `.jar`；不解压、不执行、不递归目录；文件名必须是单段合法名；
目标路径用 `SafeCombine` 确认仍在 mods 目录内；只读取 `fabric.mod.json`（不加载类）；
先写临时文件再原子改名。

### 2. 模组预设导入 / 导出

**痛点**：配一套模组给朋友，只能一个一个截图文件名。

**现在**：导出成 JSON 文件发给朋友，对方导入即可批量安装。

```
模组页 → 导出模组预设 → 得到 my-mods.rllmods.json
朋友：模组页 → 导入模组预设 → 自动挑兼容版本批量装
```

文件格式（人可读、可手改、可进版本库）：

```json
{
  "Format": 1,
  "MinecraftVersion": "1.20.1",
  "Loader": "fabric",
  "Mods": [ { "Slug": "sodium", "Version": "0.5.8", "Title": "钠 Sodium" } ]
}
```

**单个模组装不上不影响其余**——预设里常有一两个当前版本不兼容的，
用户更希望"能装的都装上"；失败的条目与原因会明确列出来。

### 3. 游戏崩溃自动分析

以前游戏崩了，用户得自己切到「日志」页点按钮——而这恰恰是最需要帮助的时刻。

现在游戏**异常退出**（退出码非 0）时自动分析崩溃日志，弹出结论摘要，
完整内容同时写入日志页。正常退出不打扰，分析不出已知模式时只在日志留一行。

### 4. 下载速度与剩余时间

首次安装要下几百 MB 到 1–2 GB，只有百分比时用户完全无法判断要等多久。

现在额外显示实时速度（`12.4 MB/s`）与预计剩余（`约 2 分 30 秒`）。

速度用**滑动窗口**（最近 5 个样本）而非全程平均——网络刚起步时样本太少，
全程平均会把瞬时速度拉平，看起来像卡死。样本不足时不给速度与 ETA，
避免出现「剩余 999 小时」这种吓人的假数字。

## 与 1.4.2 的关系

1.4.2 是安全加固（8 个缺陷），1.4.3 是纯功能新增，**两者无行为冲突**，
配置完全向后兼容，无需迁移。

## 下一步建议

按审查报告 §7 的优先级：

1. **F-2 模组索引** —— 把四套各自为政的模组识别逻辑（`ModManager` / `ModDuplicates` /
   `ModDependencyScanner` / `FindOutdatedModFile`）收敛成一份以 `fabric.mod.json` 的 id
   为主键的数据源。这是 F-1（批量更新）、F-4（依赖完整性检查）的共同地基。
2. **F-3 下载断点续传** —— 配合本次的速度显示，"还要下多久"已经可知，
   但断网重来仍是痛点。
3. **F-1 模组批量更新** —— 依赖 F-2。

不建议做：微软正版登录（F-9）、Forge/Quilt（F-10）。
