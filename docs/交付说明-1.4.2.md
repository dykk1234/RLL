# 交付说明 — RLL 1.4.2

## 一句话

安全加固版本：修掉 4 个能复现的高优先级缺陷（其中 2 个会直接导致用户启动失败），
并补齐 35 项回归测试把这些问题钉死。

## 这次修了什么

### 会让用户启动失败的两个（重要）

**1. `@argfile` 路径没加引号 → Windows 用户名带空格就起不来**

参数文件放在 `%APPDATA%\rll\`，而 `%APPDATA%` 里含用户名。旧代码拼的是
`"@" + argFile`，没加引号。Windows 拆命令行时按空格切，于是
`@C:\Users\John Smith\AppData\...` 被拆成 3 段，Java 拿到的是残缺路径 →「找不到参数文件」。

触发条件是命令行超 30000 字符，也就是**模组特别多的用户**——恰好是最需要这个功能的人。

修复：`"@" + CommandLine.QuoteArgument(argFile)`。

**2. `@argfile` 在 Java 还没读它的时候就被删了**

旧代码在 `finally` 里立刻删参数文件，但 `Process.Start` 只是把进程创建出来，
Java 还没来得及打开文件。这是个真实的竞态，表现是**偶发**启动失败或者
游戏带着空参数启动（所有 Mod 都不生效）——这类问题最难排查。

修复：参数文件改到游戏进程退出后再删；启动失败时立刻删；关窗口时兜底删。

### 安全类

**3. Java JRE 解压有路径穿越（zip-slip）**

条目名完全来自远程 ZIP，却没做路径校验就 `Path.Combine` 写盘。
含 `../` 的条目能写到解压目录外面。

已用构造的恶意 ZIP 实测复现（文件确实落在目录外），修复后被拦截。
现在和其它解压链路（原生库、Mod 文件）用同一套 `SafeCombine` 校验。

**4. Java 下载的 SHA256 校验是"可选"的**

API 少给一个 `checksum` 字段就整段跳过校验——和上一条叠加就很危险。
改成**缺失即拒绝**。Adoptium 正常一定给 checksum，不影响正常用户。

**5. Wintun 驱动库下载没有哈希校验**

`wintun.dll` 是内核态驱动，却是唯一一个没有内容哈希保护的系统级驱动下载。
已加上官方公布的 SHA2-256 硬校验。

**6. 异地联机密钥明文写进了日志**

密钥就是那个网络的准入凭证。旧代码把完整启动参数写进日志。
而日志文件**没有**像 `config.json` 那样收紧 ACL，同机其他账户可读；
用户贴日志求助还会外泄。

修复：日志里密钥显示为 `****`；日志目录和日志文件的 ACL 一并收紧。

### 正确性类

**7. classpath 交给了远端 JSON 决定**

旧注释说"会用自己拼装的 classpath 覆盖它"，实际行为是"跳过追加"——
版本 JSON 里写了字面路径的话，启动器拼好的完整 classpath 就被丢了。
现在版本 JSON 里的 `-cp` 一律丢弃，**始终**由启动器提供，命令行保证只有一个 `-cp`。

**8. 被禁用的模组不参与同步与检测**

四个模块各自用不同的 glob 推断 mods 目录内容，只有 `ModManager` 认 `.jar.disabled`。
结果是：禁用状态在目录切换时丢失、重复模组检测漏报、依赖检查误报「缺少前置」。

新增 `InstancePaths.ListModFiles` 作为唯一数据源，全部改用它。

## 验证

| 项目 | 结果 |
| --- | --- |
| 离线单元测试 | **656 项通过，0 失败**（原 621 + 新增 35） |

新增的 35 项回归测试覆盖：@argfile 引号、JRE 路径穿越拒绝、密钥脱敏、
SHA256 格式校验、classpath 归属、禁用模组同步与重复检测。

## 升级注意

- 配置文件向后兼容，无需迁移。
- 日志 ACL 收紧后，如果你的环境靠组策略共享日志目录，需要留意。
- 旧的日志文件不会自动改 ACL（只收紧当天新建的与目录本身）。

## 还没做的（见审查报告 §7 Roadmap）

优先做的三项：**模组索引**（F-2，四套匹配逻辑收敛成一份数据源）、
**下载断点续传**（F-3，几百 MB 断网重下的痛点）、
**资源包/光影包管理**（F-5，复用现有 Modrinth 链路）。

明确不建议做的：微软正版登录（F-9）、Forge/Quilt（F-10）。
