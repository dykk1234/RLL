# 交付说明 — RLL 1.4.5

## 一句话

解决「点击下载 Java 却无反应」，并把 Java 安装流程的反馈补全。

## 先说结论：后端是好的，问题全在 UI 反馈

我把整条链路逐段实测：

| 环节 | 实测 |
| --- | --- |
| `api.adoptium.net` 白名单 | 通过 |
| `JavaInstaller.QueryAsync(21)` | 成功，jdk-21.0.13+9 / 46MB / SHA256 |
| GitHub 302 → `release-assets.githubusercontent.com` | 每一跳都通过校验 |
| 实际下载首字节 | **588 ms** |

**所以不是没点上，也不是网络问题。** 用户看到的"无反应"是三件事叠加。

## 三个成因与对应修复

### ① 点击后有最长达 40 秒的「无反馈静默期」

`DownloadJavaAsync` 先 `await QueryAsync(...)`（网络请求），**之后才弹确认框**。
而查询用的是元数据的默认超时 —— **60 秒 x 3 次重试**，最坏接近 3 分钟。
这段时间唯一的反馈是**状态栏最底部一行灰字**。

**修复**：
- 新增 `HttpUtil.GetStringAsyncQuick`（**20 秒 x 2 次**），专供交互式小查询；
- 查询期间用**页面顶部的提示条**反馈（状态栏那行小字不够显眼）。

实测：查询耗时从"最长 3 分钟"变成 **1.4 秒**。

### ② `_busy` 时点击被静默吞掉

```csharp
// DownloadJavaClick：静默 return
if (_busy) { return; }

// DownloadJavaAsync：同一逻辑，却有提示
if (_busy) { MessageBox.Show("当前有其它任务在进行..."); return; }
```

更关键的是：**`_downloadJavaButton.Enabled` 全代码库从未被赋值过**
（旁边「检测 Java」「浏览...」都会正确变灰）。于是按钮**看起来可点，点了毫无反应**。

**修复**：加提示 + 按钮启用状态与其它按钮一致。

### ③ 按钮只在启动页

用户装完原版后最可能停在**下载页**，而引导弹窗只在**点过「检测 Java」**后才出现。

**修复**：**下载页也加一个「下载 Java」入口**，两者共用同一套逻辑。

## 顺带改进

**安装流程的四个阶段现在都有反馈**：

```
查询  →  下载  →  校验  →  解压
 ✓        ✓       ✓        ✓
```

以前**校验**（算 46MB 的 SHA256）和**解压**（解 47MB 的 zip）阶段
完全没反馈，进度条停在 100% 不动 —— 用户以为卡死了。

新增 `JavaInstaller.InstallAsync` 的 `onStatus` 回调，在这两个阶段给出提示。

**失败诊断从「技术错误」变成「可执行建议」**：

| 失败类型 | 新提示 |
| --- | --- |
| 域名被安全策略拦截 | 提示升级启动器版本（而不是让用户反复重试） |
| 连不上服务器 | 提示检查网络与代理 + 手动下载出口 |
| 超时 | 明确说是超时，可能网络太慢或被墙 |
| SHA256 不符 | 说明文件可能不完整，建议重试 |
| 压缩包结构异常 | 说明已拒绝安装，建议重试或手动下载 |
| 没找到 javaw.exe | 说明文件可能损坏 |
| 权限不足 | 提示换目录或以管理员运行一次 |
| 用户取消 | 明确说已取消 |

**顺带修正**：`javaPanel.ColumnCount` 写成 3 却往第 3 列加控件。
WinForms 会自动扩容（不崩），但第 4 个 `ColumnStyle` 会被静默忽略，列宽计算与预期不符。已改为 4。

## 下一步建议

按上一轮分析报告的优先级：

1. **日志轮转/归档**（实测 42 MB/小时 → 30 天 30 GB，`Log.cs` 至今无保留策略）
2. **下载断点续传 + 超时分离**（慢网络下 200MB 文件会被 15 分钟硬超时掐断）
3. **版本清单 ETag 缓存**（每次刷新重下 1–2MB）
4. **模组 id 索引**（`ModIndex`）→ 批量更新、依赖检查的共同地基
